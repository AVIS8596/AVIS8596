# Meme 扫链机器人 · 部署与使用指南（GMGN 版）

支持 Solana、BSC、Ethereum、Base、罗宾汉链（Robinhood Chain）五条链。**数据和下单都走 GMGN 官方 API**（openapi.gmgn.ai）。

- **聪明钱发现**：数据来自 GMGN 的聪明钱/KOL 交易流和热门币顶级交易者，再逐个用 GMGN 钱包统计核实。核实标准是近 30 天已实现利润 ≥ 50 SOL（EVM 链按美元等值换算）、胜率 ≥ 60%，并排除高频机器人。
- **实时监听**：同时用两路，互为备份，同一笔交易自动去重。
  - 链上 WebSocket：Helius / QuickNode，延迟最低
  - GMGN 交易流：每 3 秒轮询一次
- **新币发现**：GMGN trenches，覆盖 pump.fun、four.meme、clanker、zora 等几十个平台的毕业币和即将毕业币；另外用 PumpPortal 监听 pump.fun 迁移。
- **筹码分析**：两套结果交叉验证，持仓比例取较大值。
  - 自己还原开盘：同区块买入、同一出资人、金额相近、新钱包
  - GMGN 的持币人标签：bundler 捆绑、rat_trader 老鼠仓、sniper 狙击
- **安全检测**：铸币和冻结权限、貔貅盘、无法卖出、买卖税。GMGN 和 GoPlus 双重检查。
- **下单**：通过 GMGN 下单（`/v1/trade/swap`），默认开启防夹（Base 不支持）。
- **交易功能**：跟单、自动交易、分批止盈、止损、移动止损、超时卖出、跟随带单钱包卖出。
- **风控**：每日亏损上限、持仓数上限、单币冷却期、Gas 上限、余额预留。

> ⚠️ 默认是**模拟盘**（`dry_run: true`）。建议先跑 3~7 天，再切实盘。
> ⚠️ 用 GMGN 下单时，资金放在绑定到 API Key 的 GMGN 钱包里，相当于把资金安全交给了 GMGN。只放你能承受全部亏光的金额。

### 1. Telegram
1. 在 Telegram 搜索 **@BotFather**，发送 `/newbot`，按提示起名字，拿到 token，填入 `TELEGRAM_BOT_TOKEN`。
2. 找到你刚建的机器人，**点 Start**。
3. 搜索 **@userinfobot**，点 Start，它会回复你的数字 ID，填入 `TELEGRAM_CHAT_ID`。

### 2. GMGN API（最关键，按顺序做）
1. **准备交易钱包**：登录 gmgn.ai，确认你的 GMGN 交易钱包，并往里充值准备用来交易的资金。Solana 钱包放 SOL，EVM 钱包放 BNB 或 ETH。
2. **在服务器上生成签名密钥**（先按第三节第 2 步装好机器人）：
   ```bash
   cd ~/memebot
   openssl genpkey -algorithm ed25519 -out gmgn_private.pem
   chmod 600 gmgn_private.pem
   openssl pkey -in gmgn_private.pem -pubout      # 输出的就是公钥，复制下来
   ```
   这个私钥只用来给 API 请求签名，不是钱包私钥，不要发给任何人。
3. **申请 API**：打开 **gmgn.ai/ai**，提交申请，把上一步的公钥填进去。官方审核后会把你加入白名单（每天处理一次），批下来后复制 API Key，填入 `GMGN_API_KEY`。
4. **设置 IP 白名单**（交易必须做）：在服务器上执行 `curl -4 ip.me`，把得到的 IPv4 地址填到 GMGN API 后台的白名单里。
5. **关闭服务器的 IPv6**（GMGN 只支持 IPv4，不关会出现 401/403 错误）：
   ```bash
   echo -e "net.ipv6.conf.all.disable_ipv6=1\nnet.ipv6.conf.default.disable_ipv6=1" | sudo tee /etc/sysctl.d/99-no-ipv6.conf
   sudo sysctl --system
   ```
6. **填写钱包地址**：把绑定在 API Key 上的钱包地址填入 `GMGN_WALLET_SOL` 和 `GMGN_WALLET_EVM`。不确定地址的话，跑一次 `main.py check`，它会打印 GMGN 返回的绑定信息。
7. 在 `config.yaml` 里把 `gmgn.plan` 改成你买的套餐（free / plus / pro），机器人会按对应速度限流。

### 3. Helius（Solana 节点）
官网 helius.dev 注册 → API Keys，复制后填入 `HELIUS_API_KEY`。然后升级到 Developer 套餐。

### 4. QuickNode（ETH / BSC / Base 节点）
注册后分别创建 Ethereum、BNB Smart Chain、Base 三个主网节点。把每个节点的 HTTP 和 WSS 地址填入 `.env` 里对应的 `*_RPC_HTTP` 和 `*_RPC_WSS`。

## 三、部署步骤

```bash
# 1. 登录服务器，下载代码到 ~/memebot（已有 gmgn_private.pem 也没关系，不会被覆盖）
mkdir -p ~/memebot && cd ~/memebot
git init -q
git remote add origin https://github.com/AVIS8596/avis8596
git fetch -q origin claude/memebot
git checkout -q -b claude/memebot FETCH_HEAD

# 2. 安装
bash deploy/install.sh

# 3. 按第二节生成 GMGN 密钥、申请 API、加白名单（代码已强制走 IPv4，关 IPv6 可跳过）

# 4. 填写 key（一问一答，粘贴后回车即可）
python3 deploy/setup_env.py

# 5. 检查所有 key（会给你的 TG 发一条测试消息）
.venv/bin/python main.py check

# 6. 启动（默认模拟盘）
sudo systemctl start memebot
tail -f logs/memebot.log
```

### 切换实盘
1. 编辑 `config.yaml`，把 `dry_run: true` 改成 `false`。
2. 再跑一次 `main.py check`。会多检查三项：GMGN 交易签名、IP 白名单、各链交易钱包余额。
3. 执行 `sudo systemctl restart memebot`。

| 操作 | 命令 |
|---|---|

### 卖出规则（11-08 起：让利润奔跑）

回放回测发现：跟卖聪明钱、"涨不上去就卖"、移动止损把后来大涨的币提前卖掉了。同一批入场只用 **止损 -35% + 分批止盈（+100% 卖一半出本、+300% 再卖一半；优质档 +100% / +300% / +1000%）+ 最长持有 24 小时（优质 72 小时）**，结果从亏钱变成赚钱（去掉最大赢家后依然更好）。所以这三条先关闭，旧规则作为对照一直保留在 `/backtest` 里，数据变了随时可以改回。

**出本只卖刚好回本的部分（`exit.recover_cost_only`）**：涨到 +100% 时卖出"刚好收回本金"的比例（多卖 5% 覆盖成本）——正好翻倍卖约一半；如果一下子冲到 4 倍才第一次检查到，只卖约 1/4，5 倍约 1/5；之前部分卖出过的金额也算进去。剩下的全是利润，交给强势长拿。`/backtest` 里有"出本固定卖一半"做对照。

**强势长拿（config 里 `exit.runner`）**：一个币涨到翻倍、卖一半出本之后，就当它已经证明自己是好币，剩下的不再按固定的 +300% 止盈，也不受 24/72 小时限制，一直拿着，直到上涨变疲软才分批卖：
- 从最高点回撤 25% 卖 1/3，回撤 40% 再卖一半，回撤 55% 全卖（每档都要连续两次确认，防插针）
- 涨幅跌回 +20% 一次全卖（保住利润）
- 最长拿 7 天
`/backtest` 里有「不用强势长拿（固定止盈）」和「强势长拿·回撤更宽（35/50/65%）」两套对照，数据够了可以按结果调整回撤档位。

### 分档买卖规则（旧，供参考）

| 档位 | 每笔 | 止损 | 涨不上去就卖 | 最长持有 | 止盈 | 移动止损 | 带单钱包卖出 |
|---|---|---|---|---|---|---|---|
| 一般 | 0.05 SOL | -35% | 1 小时没到 +15% | 6 小时 | +100% 卖一半，+300% 再卖一半 | 涨过 +60% 后回撤 30% | 全卖 |
| 👍 较好 | 0.1 SOL | -35% | 4 小时没到 +20% | 24 小时 | 同上 | 同上 | 全卖 |
| 🔥 优质 | 0.2 SOL | -35% | 12 小时没到 +30% | 72 小时 | +100% 卖一半出本，+300% 卖 30%，+1000% 再卖一半 | 涨过 +80% 后回撤 35% | 跟卖一半 |

已经止盈过一次的持仓不受"涨不上去"规则影响，交给移动止损处理。

- **移动止损先卖一半**：还没止盈过时触发移动止损，先卖一半锁定利润，剩下一半从当时的价格重新算最高点（回调后再拉升还能吃到）；剩下的跌回成本就卖。
- **防插针**：止损和移动止损要连续两次检查（约 10 秒）都触发才卖；跌破 -50% 不等，立刻卖。规则在 `config.yaml` 的 `exit.tiers` 里改；分档功能上线前买的老持仓仍按原来的统一规则。

### 扩大钱包池（不只看 GMGN 的聪明钱标签）

| 来源 | 怎么找 | 类别 |
|---|---|---|
| 大涨币挖矿（每 2 小时） | 结果档案里 4 小时涨 3 倍以上的币 + GMGN 6h/24h 热门榜市值 ≥ $50 万的币，拉盈利前 50 名 | 3 个以上大涨币都赚钱：🎯精准钱包；2 个以上大涨币都在发币 3 分钟~6 小时、市值 ≤ $30 万时买入：🔭早期发现者；多次带狙击/捆绑/老鼠仓/dev 标签：🕵️阴谋地址；带 KOL 标签：📣KOL |
| KOL（每 6 小时） | GMGN KOL 交易流里 30 天已实现利润前 30 名 | 📣KOL：单独买不跟，只计入共振 |
| 信号质量（每小时） | 每个钱包最近 7 天买过的币，1 小时后中位涨跌 | 跟它买明显亏的不单独跟、样本多且持续亏的移出；跟它买确实赚的，即使快进快出也允许单独跟（有确认期） |

分析报告会显示阴谋地址 / 早期发现者 / 精准钱包现在的持仓比例，并记入结果档案，让数据决定它们在场时该买还是该躲。`/wallets` 按"跟它买 1 小时后的中位涨跌"排序。

### 买入时机与过滤

- **稳的钱包才单独跟**：一个聪明钱买入就跟，要求它平均持仓 ≥ 10 分钟（GMGN 统计 + 机器人自己观察到的最近买卖），并且跟单战绩不差（满 8 笔胜率不低于 40%）。快进快出的钱包照样监听，但要 2 个以上聪明钱一起买才跟。
- **30 秒确认期**：信号出现后等 30 秒，带单钱包已经卖了、价格涨超 25% 或跌超 15% 都不买。
- **不追高**：1 小时已涨超 300% 不买（3 个以上聪明钱一起买除外）。
- **下单前复查（用最新数据）**：确认期结束、真正下单前，分析报告只要超过 20 秒就重新完整分析一次——价格、持有人、流动性、筹码、还拿着的聪明钱全部用现在的数据，再过一遍所有风控。拿不到最新数据就不买。
- **正在砸盘不买**：最近 5 分钟跌超 20% 的不买，几个聪明钱都不例外。
- **只认还拿着的聪明钱**：买过但已经卖掉的聪明钱不算买入理由，也不算进"3 个聪明钱可以追高"的例外。
- **反应速度**：聪明钱链上实时推送（Solana / EVM WebSocket）+ GMGN 交易流每 3 秒；主动建仓每 15 秒扫一次快毕业 / 已毕业列表；新币列表每 20 秒；新币出现 20 秒后分析；确认期 20 秒。
- **钱包体检（跟单前审钱包）**：每个聪明钱都会体检（新钱包优先、24 小时有效，可疑的 7 天后复查；确认期里也会顺便给带单钱包体检）：
  ① 割完即死——它赚钱的币（至少 6 个取得到现价）有 80% 以上在它卖出后跌了 90% 以上，而且中位只拿 1 小时以内（取不到现价的不算）；② 同名多合约——买了 2 个以上同名的不同合约，而且这个名字让我们亏光过（同名跟风盘很常见，不算）；③ 被标记过——机器人分析过的币里 3 次以上被认定为捆绑 / 埋伏 / 项目方；④ 跟项目方走得近——买了同一个项目方发的 2 个以上的币且项目方上了黑名单，或买了它发的 4 个以上。任意一条 → 标为可疑：不再监听、不计入聪明钱人数、不能当买入理由。⑤ 开盘狙击型（大多数币发币 30 秒内就买）不单独跟。
  每次跟单还会看：带单钱包是不是就是这个币的项目方 / 老鼠仓 / 开盘狙击（"捆绑"不算：快手聪明钱同区块买入也会被判成捆绑，影子单显示拦错了钱），是就不跟，也不算进"几个聪明钱"。`/audit 钱包地址` 手动体检。
- **阴谋团伙**：每 2 小时用最近 3 天分析过的币，把总是一起出现在早期可疑买家（捆绑 / 老鼠仓 / 狙击）里的钱包归成团伙（两两一起出现在 3 个以上的币里、至少 3 个人）。新币的早期买家里有同一个团伙的 3 个以上成员 → 团伙盘不买。已知阴谋地址合计持仓 ≥ 20% 也不买。团伙成员数记进结果档案让模型学。
- **影子单**：每个被拦下的信号满 4 小时后，拉真实 K 线按真实卖出规则完整模拟一遍（止损、出本、强势长拿），每日复盘里每条拦截规则都会显示"影子单 N 笔每笔 X%"——为负说明拦得对，为正说明这条拦错了钱。下单严格、数据照样多。
- **坏人记忆**：亏光（≥80%，撤池子 / 项目方砸盘）的单子，记住项目方（30 天不碰它发的任何币）和币名（48 小时内同名重发不买）；24 小时内买过同名币的不再买另一个同名合约；项目方以前发过 15 个币以上、或 7 天内机器人见过它发 3 个以上别的币，不买（批量发币）；带机器人买进亏光币的钱包 7 天内第 2 次就移出监听（多半是项目方自己的号或老鼠仓）。项目方发币数、是否已卖光、LP 是否销毁也记进结果档案，让模型学。
- **不在山顶接**：发币 24 小时内、价格已经是发币价 10 倍以上的不买（3 个以上聪明钱一起买除外）。这条和其他过滤一样记入"被过滤的信号"，每日复盘里能看到它拦下的币 1 小时后是涨是跌，拦错了就放宽（`max_launch_multiple`）。
- **不接飞刀**：从 2 小时内的最高价已经跌了 60% 以上不买（3 个以上聪明钱一起买除外）。
- **试探单不跟**：聪明钱买入不到 0.2 SOL 的小单不单独跟。
- **止损过的币 24 小时内不再买**；其他平仓后 2 小时冷却。
- **单笔不超过池子流动性的 3%**：池子太小时自动减少买入量。
- **归零清理**：持有满 1 小时且 30 分钟取不到价格（多半已归零/下架），实盘尝试清仓、模拟盘按归零平仓，避免占满持仓名额。
- **市值虚高过滤**：市值 ≥ $3M 且超过 1 小时成交量 500 倍，不买也不推送。
- **卖压过滤**：1 小时卖出笔数超过买入 1.5 倍不买；持有人少于 80 不买。
- **跟卖要过半**：多个聪明钱一起带单的，要超过半数卖出才跟卖；只有一个钱包带单的，它卖就跟。
- **连亏熔断**：连续 4 笔亏损平仓，暂停买入 60 分钟（`/resume` 可立即恢复）。
- **过滤复盘**：被拦下的信号会记录下来，1 小时后回看价格，每日复盘里按原因统计"拦得对不对"，用来调整过滤条件。

### 主动建仓（不等聪明钱）

机器人每 30 秒扫一遍 GMGN 的"快毕业"和"已毕业"列表，两种情况会主动小仓位建仓：

| 策略 | 触发条件 | 仓位 |
|---|---|---|
| 早期建仓 | 快毕业、发币 3 小时内、持有人 ≥ 100 且 3 分钟内增长 ≥ 15%、累计成交 ≥ $1.5 万；跑路风险 / 前10 / 捆绑 / 老鼠仓 / dev 持仓都很低 | 一般档；有 2 个以上聪明钱或 KOL 用较好档 |
| 强叙事 | 市场注意力评分 ≥ 60：KOL 持有、聪明钱、绑定大号 12 小时内的新推文、项目 X 粉丝、社交齐全、付费推广、同名币扎堆且它领跑、成交火热；结构不能太差 | 一般档 |

- **后台论证**，每一步都通过才下单：
  1. 达标后先进观察名单，早期建仓观察 1 分钟、强叙事观察 3 分钟（叙事分 ≥ 90 只观察 1 分钟），期间仍然达标、持有人没明显减少（少 5% 以上才算）、叙事分没明显下降才继续；
  2. 完整分析后的代币评分要达标（早期 ≥ 50、叙事 ≥ 55），没通过的记入"被过滤的信号"；
  3. 照常过所有风控过滤（捆绑、埋伏、筹码、市值虚高、卖压、追高……）；
  4. 30 秒确认期，价格没拉飞、没砸盘。
- 同名跟风盘不碰；两类合计每小时最多 2 笔，每类每天最多 6 笔（`config.yaml` 的 `strategies` 里改）。
- 买入后交给动态持仓管理：数据变差提前卖、涨不上去就卖、止损照常。
- "叙事"是用注意力数据近似，不理解新闻内容；要更早发现项目方/KOL 发的 CA，需要 X 推特监控。

### 🧪 试探仓（强信号只因筹码"表面指标"超限被拦时）

刚发币的几分钟里，前10持仓、捆绑比例天然偏高，正常的筹码上限会把最早的好币拦在门外（例：「牛逼」叙事分 95，只因前10持仓 45.1% > 40% 没买；TREMP 叙事分 95，只因捆绑交易 55% > 30% 没买）。

但**不能整体放松**：11-10 的日报里，主动建仓被拦下的 163 个信号，1 小时后大跌的 99 个、大涨的只有 14 个，影子单每笔 -30%——拦下的绝大多数确实该拦。所以只对最强的一小撮、用小仓位做实验：

- **什么时候开**：被拦的原因**只是**前10持仓 / 捆绑这两个表面指标超限，而且信号够强——
  - 强叙事 ≥ 80 分（扫描阶段：前10 ≤ 65%、捆绑交易占成交量 ≤ 60%）；
  - 早期建仓、新币高评分、模型买入；或跟单时有 ≥ 2 个**还拿着**的聪明钱（不算项目方 / 老鼠仓 / 开盘狙击）。
- **完整分析时的宽松上限**：前10 ≤ 65%、捆绑地址**现在还拿着的** ≤ 45%；超过还是不买。
- **不放宽的**（直接说明是阴谋盘的证据）：埋伏 / 老鼠仓、刷量、跑路风险、dev 持仓、已知阴谋地址、团伙盘、坏项目方、同名重发、批量发币、蜜罐、砸盘、飞刀、涨幅已兑现。早期建仓的扫描上限也不放宽（自我学习按数据把它的捆绑上限从 15% 收紧到了 10%）。
- **仓位**：正常仓位 × 0.25，买入理由里会写「试探仓：……先小仓位建仓再观察」。买入后照常止损、出本、强势长拿。
- **单独记账**：日报「按买入来源」里试探仓单独一行，按战绩分配仓位也单独算——赚钱会自动加仓，亏钱会自动再缩小；日报「被过滤的信号」里「强叙事结构不过关」也单独一行，几天后就知道这条线该松还是该紧。不想要就把 `config.yaml` 里 `trading.probe.enabled` 改成 `false`。
- **早点买，而不是等涨上去**：叙事分 ≥ 90 的观察期从 3 分钟缩短到 1 分钟；观察期内持有人少 5% 以上才算热度回落（以前少 1 个人就放弃），放弃时会写明是持有人还是叙事分掉了。

### 启用 BSC / ETH / Base

```
python3 deploy/enable_evm.py bsc base ethereum   # 用 PublicNode 免费公共节点（不用注册），已填过自己节点的链保留不动
python3 deploy/enable_evm.py off                 # 全部关闭
sudo systemctl restart memebot
```
公共节点有限速，模拟盘够用；实盘或监听钱包多时建议换成 Alchemy 免费账号的节点（重新运行 `deploy/setup_env.py` 填入）。
注意：模拟盘没有计算 EVM 的 Gas 费，ETH 主网小额交易的 Gas 可能占好几个百分点，模拟结果会偏乐观。

### 罗宾汉链（Robinhood Chain）

- 默认已启用（模拟盘），不用填任何节点：机器人内置免费公共节点 `rpc.nodeflare.app`。公共节点没有 WebSocket，聪明钱监听改成每 4 秒查一次新区块（比 WebSocket 慢几秒）；以后有自己的节点，在 `.env` 填 `ROBINHOOD_RPC_HTTP` / `ROBINHOOD_RPC_WSS` 就会自动换成实时推送。
- GMGN 支持它的新币列表、热门榜、代币信息、安全检测、持币人、K 线、钱包记录和下单，但**还没有它的聪明钱 / KOL 交易流**。所以这条链的钱包靠两种方式找：每 3 小时从热门币盈利前排里核实聪明钱，每 2 小时从大涨币里挖精准钱包和早期发现者。刚开始几天能跟的钱包会比较少，主动建仓（早期、强叙事）不受影响。
- GoPlus 不支持这条链，安全检测只用 GMGN 的。Gas 用 ETH，价格取不到时按主网 ETH 计。
- 关闭：`python3 deploy/enable_evm.py off` 会连同罗宾汉链一起关；只开它：`python3 deploy/enable_evm.py robinhood`。
- TG 命令里链名写 `robinhood` 或简写 `hood`；`/whynot`、`/learn token` 遇到 0x 地址会自动识别是哪条链。
- 模拟盘同时持仓上限放宽到 30 个（`max_open_positions_dry`），5 条链一起跑也不会因为名额满而漏掉数据。

### 运维

- 每天 21:00 复盘后自动维护：清理 30 天前的信号流水，备份数据库到 `data/backup/`（保留最近 3 份）。结果档案、交易记录、钱包和画像不删——那是机器人的记忆，不要删除 `data/` 目录。
- 已平仓持仓的观察模拟每分钟取一次价、平仓 24 小时后结束；健康分复查只对持仓和平仓 6 小时内的模拟做，节省接口额度。
- 余额不足的提醒一小时最多一次。

### 向高手学习

- **钱包来源**：手动发 `/learn 钱包地址`（比如 GMGN 排行榜上的人），加上每天自动从 GMGN 的 KOL / 聪明钱交易流里按 30 天已实现利润取前 20 名。
- **交易画像**：每人最近约 200 笔交易 + 100 个持仓，统计入场（发币后多久、入场市值、是否毕业前买）、仓位、持有时长、第一次止盈、亏多少砍仓、利润是否靠少数大单、常用平台，并给一个风格标签（狙击型 / 早期型 / 趋势型 × 秒进秒出 / 快进快出 / 日内波段）。
- **共同规律和建议**：对比机器人当前参数给出建议（只建议不自动改，先观察验证）。学不到他们的消息来源，狙击型的单也跟不上。
- 最近 30 天依然达到聪明钱标准的人自动加入监听，照常要过论证和确认期。
- 狙击 / 秒进秒出的程序化钱包标 🤖，只看不学。
- 学到的习惯放进观察模式的第三套规则「高手规则」（止损 -20%、+30%/+60% 分批止盈、最多拿 2 小时），和旧规则一起模拟对比，效果好再考虑正式使用。

### 期望值、回测、市场冷热

- **期望值**：复盘里给出每笔期望 = 胜率 × 平均赚 + 败率 × 平均亏（含成本）、盈亏比、利润因子，以及"大赢家占多少利润"和"卖飞"（平仓后 4 小时内又涨到卖出价 2 倍以上）的笔数和原因。meme 币看期望值，不看胜率。
- **回放回测** `/backtest`：用真实入场按 8 套卖出规则（当前、不跟卖、高手规则、止损 -25%、早止盈、观察期 1 小时、移动止损放宽、拿满）重新模拟，按每笔期望排名。改规则前先回测。
- **市场冷热**：看最近 6 小时分析过的币 1 小时后的整体涨跌。冷市仓位 ×0.5（可设为暂停买入），`/status` 和复盘里显示当前状态。

### 🧠 自我学习（每笔交易都是一次学习）

1. **每笔复盘**：平仓满 4 小时后自动打"教训"标签——买在高位 / 卖早了 / 止损后又涨回来 / 止损及时 / 拿住大赢家。有毛病的单子会推送一条 📚 复盘（静音提醒时不推），每日复盘汇总最近 7 天每类教训的笔数和金额，指出"最大的毛病"。
2. **漏掉的好币**：机器人看过、之后涨了 3 倍以上却没买的币，逐个查当时卡在哪：风控过滤（哪一条）、主动建仓卡在哪个条件、新币评分不够、聪明钱不够。每日复盘里统计"漏掉的好币卡在哪条规则"。
3. **自动调参**（每 6 小时一次）：
   - 数据：结果档案（每个分析过的币之后 1 小时 / 4 小时的价格），加上**早期观察样本**——每个快毕业的币每 2.5 分钟记一份快照（持有人、成交、结构），用来试"早期建仓条件放宽或收紧后，会在第几份快照时买入、结果如何"，这是让入场更早的关键。
   - 方法：一组参数（新币评分门槛、聪明钱个数、不追高、持有人、捆绑 / 埋伏 / 前10上限，早期建仓的持有人、增长、成交、结构上限）逐个试相邻一档，按"止损 -35% + 拿 4 小时"近似算收益。
   - 只有这三条都满足才算学到：前 60% 和后 40% 两段数据都更好；改变了足够多的币（≥15 个，早期 ≥10 个）；去掉最赚的一个依然更好。
   - 模拟盘自动生效：每次最多改一个参数，同一参数 24 小时内不重复改，每个参数都有上下限。实盘只发建议，`/tune apply` 才生效。
   - 学到的参数存在数据库里，覆盖配置文件，重启不丢；`/tune reset` 一键恢复配置文件的值；`/tune off` 关闭。
4. 这是统计意义上的学习：样本越多越准（一般要两三天以上），它学不会"理解"新闻和叙事；每个改动和理由都会推送到 TG，你随时可以否决。

### 🤖 自己的选币模型（目标：自己当聪明钱，不靠跟单）

- **两个模型**：分析模型——用每个被完整分析过的币当时的 24 项数据（评分、流动性、市值、持有人、成交、涨幅、买卖比、成交/市值、筹码、聪明钱 / 阴谋地址 / 早期发现者占比、链、来源……）预测之后会不会大涨；早期模型——用快毕业的币每 2.5 分钟的快照加走势（持有人每分钟增长、成交增长、比第一次看到涨了多少、上线多久）预测，目标是比评分更早发现好币。
- **怎么学**：梯度提升决策树（纯 Python，不用装库），标签是"之后 4 小时按止损 -35% 近似，扣成本后赚 50% 以上"。按时间切开，前 70% 训练、后 30% 检验，用检验集定"多高的分数值得买"。区分能力 AUC < 0.6 或找不到"高分组平均赚 10% 以上"的分数线 → 不合格，不选币。每天用最新数据重训。
- **上线流程**：先影子模式（只记录"模型会买什么"，4 小时后看结果）→ **最近 24 小时**选的币有 30 个出结果、平均赚 10% 以上、中位不亏（只考现在这版模型；更早的选择是旧模型做的，不算），**模拟盘**自动让它下单（照样过全部风控和 30 秒确认期，每小时最多 3 笔）→ 之后最近 30 个选择平均转亏，自动退回影子。**实盘永远不会自动启用**。
- `/model` 看训练成绩（AUC、高分组平均收益、最看重哪些数据）、影子期选了哪些币、表现如何；`/model train` 立即训练；`/model shadow` / `on` / `off` 手动切换。每日复盘里有模型当天的成绩，买入来源里"模型买入"单独统计，可以直接和"跟单"比。
- 数据要求：分析模型至少 800 个有结果的样本（其中大涨 ≥ 40 个），早期模型至少 1500 份快照，一般跑 2~4 天就够第一次训练。

### 💸 真实成本校准

- 用实盘成交算出真实成本：卖出看成交价比下单那一刻的价格少拿多少；买入看成交价比报价多花多少（老记录用成交那一分钟的 1 分钟 K 线中间价近似）；另外统计下单失败率。
- 模拟盘每边成本取"公式估算（手续费 1% + 价格冲击）"和"实盘实测中位数"里更高的那个（实盘满 8 笔才用实测），每笔再扣固定优先费 / Gas（`trading.sim_fixed_fee_native`）。这样模拟盘的成绩≈实盘能拿到的成绩。
- **池子被抽干时按真能卖到的钱算**：价格冲击用恒定乘积池子的公式（金额 / (流动性 / 2 + 金额)，小单和以前一样 ≈ 2 × 金额 / 流动性），卖出不再封顶 30%——池子被撤走后报价还挂着，但真去卖只能拿回池子里剩的那点钱。为了不因为数据一时出错把持仓算成归零：冲击超过 30% 时隔 3 秒换数据源（GMGN 重新取 + DexScreener）复查，取几次里最大的流动性；复查拿不到数就按老办法最多扣 30%。这种成交会在卖出原因后面写「池子只剩 $X……实际只能卖回约 N%」。
- `/costs` 查看；每 6 小时自动重算。

### 📐 按战绩分配仓位

- 每种买入来源（跟单 / 新币高评分 / 早期建仓 / 强叙事 / 模型买入）和每个档位，按自己最近 7 天的真实每笔期望自动调仓位：≤ -10% ×0.25，-10%~0 ×0.5，0~+8% ×1，+8%~+20% ×1.25，≥ +20% ×1.5（加仓要求去掉最赚的一笔仍为正）。两个倍数相乘，限制在 ×0.25~×1.5，满 15 笔才调。买入消息里会写"按战绩仓位 ×0.5（跟单近 7 天 20 笔每笔 -9%）"。
- 总敞口上限：模拟盘所有持仓合计不超过 $6000（`max_exposure_usd_dry`），防止一群 meme 一起崩。

### 🧠 卖出规则也自动学

- 每天用最近 4 天的真实入场回放 K 线，试相邻的几种改法：止损线（-25/-30/-35/-45/-55%）、强势长拿回撤档位（20/35/50、25/40/55、30/45/60、35/50/65%）、强势长拿保底线（+10/+20/+35%）。
- 前 60% 和后 40% 两段都更好、去掉改进最大的一笔依然更好才改；模拟盘自动生效，实盘只建议。至少 30 笔可回放的单子才开始。

### 🛡 无人值守的安全

- **每日异地备份**：每天把精简版数据库（交易、结果档案、钱包、模型、学到的参数；去掉 K 线缓存和 3 天前的流水）压缩后发到你的 Telegram。`/backup` 立即备份。
- **恢复**：新服务器部署好后，把备份文件发给机器人，说明文字写 `/restore`；机器人检查没问题后发 `/restore confirm`（当前数据库会先另存，机器人自动重启）。

### 🚦 上实盘标准（/golive）

只看规则改版后的模拟盘单子，成本按实盘实测校准，6 项全部达标才建议上实盘：跑满 7 天；至少 150 笔；每笔期望为正；利润因子 ≥ 1.3；去掉最赚的一笔仍赚钱；一半以上的天数赚钱且最差一天不超过总盈利。每日复盘里显示进度；首次达标会提醒，并给出分阶段加钱计划（实盘先用 1/10 仓位，满 30 笔且和模拟盘差距在 15 个百分点以内才翻倍）。上实盘后持续对比实盘和模拟盘，差太多会提醒退回。

### 从结果里学习

- 每个分析过的币都会存一份**结果档案**：当时的各项数据 + 之后 15 分钟 / 1 小时 / 4 小时的价格，机器人每天分析几百个币，几天就有上千条样本。
- `/learn data` 按特征分档统计"之后涨跌"，并对比"机器人买过的"和"全部"，检验选币到底有没有效。
- 规律稳定后用来自动调整选币条件（先观察验证，再确认生效）。
- 模拟盘成交成本按"手续费 1% + 价格冲击（小单约 2 × 金额 / 流动性，池子被抽干时接近 100%）"估算；观察模式的虚拟卖出也扣 2% 估算成本，跟卖聪明钱只同步给旧规则，用来检验跟卖到底有没有用。

### 动态持仓管理

机器人每 2 分钟复查一次每个持仓，看当初买入的理由还在不在，算出 0~100 的**健康分**（70 为中性）：

| 数据 | 变差（扣分） | 变好（加分） |
|---|---|---|
| 聪明钱 | 大部分已卖出 -30，三分之一以上卖出 -15 | 买入后又有新聪明钱进场 +8 / +15 |
| 捆绑 / 埋伏地址 | 持仓比买入时少一半以上（在出货）-20 / -15 | |
| dev | 持仓少一半以上 -15 | |
| 流动性（扣除价格涨跌影响） | 少了 25% 以上 -20 | |
| 持有人 | 减少 15% 以上 -10 | 增加 20% / 50% 以上 +5 / +10 |
| 成交量（持有满 1 小时后） | 不到买入时的 20% -10 | 超过 1.5 倍 +5 |
| 新出现安全风险 | 直接 0 分 | |

- 健康分 < 40 卖一半，< 25 全卖；要**连续两次复查**都偏低才动手，避免数据抖动误卖。
- 健康分 > 80 视为强势：第 2 档以后的止盈暂缓、移动止损多容忍 10%、观察期和最长持有时间延长。
- **紧急卖出**：撤池子（流动性只剩一半以下）、dev 两次复查之间清仓 → 不等确认立刻全卖，滑点调到 30% 并加优先费。
- **保本止损**：涨过 +50% 以后，跌回成本附近（+3%，覆盖手续费）就卖，赚过的单子不会变成亏钱。
- **止损线不会因为看好而放宽**，动态管理只负责在数据变差时更早卖。
- **观察模式**（默认）：新规则只记录不执行。同一个持仓分别按旧规则和新规则虚拟卖出，满 24 小时推送对比；确认新规则更好后发 `/dynamic on` 接管。
  - 对比里不算"池子已经被撤空后才触发的紧急卖出"：那时已经卖不掉了，按报价算成交是假的（11-10 日报里动态管理的 +126%、+108% 两笔就是这种）。

## 五、识别逻辑

**聪明钱**：必须同时满足以下条件。每 24 小时复查一次，跟单的实际盈亏会修正钱包评分。
- 近 30 天已实现利润 ≥ 50 SOL 等值（每 3 小时找一轮新钱包）
- 胜率 ≥ 60%（GMGN 按"交易过的代币"计算：赚钱的币 ÷ 全部币）
- 30 天内交易过 10~1500 个币
- 平均持仓时间 ≥ 60 秒（排除高频机器人）

**捆绑地址**（dev 控制的小号），有以下任一类证据：
- 和代币创建交易在同一个 slot 或区块买入
- 同一笔交易里有多个钱包一起买入
- 出资人就是 dev，或和 dev 是同一个出资人
- 和其他早期钱包共用同一个出资人（出资人数据来自 GMGN 的首笔入金记录）
- 开盘后直接从 dev 那里收到代币
- GMGN 标记为 bundler

**埋伏地址**：开盘前不久才首次入金、并在开盘最早几个区块买入的新钱包；或被 GMGN 标记为 rat_trader（老鼠仓）。

**狙击地址**：开盘最早几个区块买入，但找不到和 dev 的关联；或被 GMGN 标记为 sniper。

## 六、已提前处理的问题

**GMGN 相关**
| 问题 | 处理方式 |
|---|---|
| 签名格式不对导致 401 | 按官方 gmgn-cli 源码实现，已用官方 Node 代码交叉验证，签名完全一致 |
| 时间戳偏差超过 5 秒被拒 | 安装脚本开启 chrony 自动校时 |
| 触发限流后被封 5 分钟，继续请求会延长封禁 | 按套餐权重主动限流（只用 80% 额度）；一旦被限流，所有 GMGN 请求统一暂停到解封时间 |
| 套餐不支持某接口 | 自动识别并停用，不会反复请求 |
| 同一错误反复触发被临时封禁 | 卖出失败后按次数递增等待时间再重试 |
| 只支持 IPv4 | 强制用 IPv4 连接，部署指南里有关闭 IPv6 的步骤 |
| 全部卖出时余额精度问题留下碎渣 | 全部卖出用百分比（10000 bps）下单 |
| 下单请求超时后重复下单 | 下单接口绝不自动重发；状态未知时先查余额确认 |
| 钱包统计接口批量查询只返回第一个 | 实测发现后改为逐个查询 |
| 交易笔数被拆单放大，误伤真聪明钱 | 改用"交易过的代币数"过滤，和 GMGN 胜率口径一致 |

**通用**
| 问题 | 处理方式 |
|---|---|
| WebSocket 断线 | 自动重连、心跳保活、重新订阅 |
| 同一笔交易重复推送 | 按交易哈希去重（链上监听和 GMGN 交易流之间也去重） |
| 空投被误判为买入 | 只认钱包自己发起、并且花了 SOL/ETH/稳定币的交易 |
| 池子地址混进聪明钱 | Solana 用"是否在曲线上"排除池子，EVM 排除合约地址 |
| 取价失败被当成归零而误止损 | 价格取不到时跳过本轮判断 |
| 节点或接口临时故障 | 单个数据源失败不影响整体分析，自动用 GMGN 数据兜底 |
| 同一个币重复买 | 每个币单独加锁，有持仓或在冷却期内都不买 |
| 同一个新币被多个来源重复推送 | 6 小时内只处理一次 |
| 卖不出的币无限重试 | 失败 5 次标记为"无法卖出"并通知你 |
| 模块崩溃拖垮整个程序 | 每个模块独立运行、出错自动重启 |
| 服务器重启 | systemd 开机自启 |
| 私钥和 key 泄露到日志 | 日志自动替换成 *** |
| TG 消息格式错误或刷屏被限流 | 自动转义，发送间隔 1.1 秒 |

## 七、已知限制

1. **资金托管在 GMGN**：用 GMGN 下单，资金不在你自己手里。如果想改回自托管，在 `config.yaml` 里设置 `trading.executor: self`，然后填 Jupiter / 0x 的 key 和钱包私钥。
2. **跟单延迟约 3~10 秒**：主要花在安全检测和筹码分析上。另外 GMGN 交易流是轮询（3 秒一次），链上 WebSocket 那一路更快。
3. **捆绑和埋伏识别是概率判断**：推送里列出了每个地址的具体证据，供你自己判断。
4. **GMGN 免费档太慢**：分析一个币要调用好几次接口，聪明钱核实每个钱包也要单独请求。免费档每秒 5 次，跑起来会明显排队，建议至少 Plus。
5. **EVM 卖出信号偏敏感**：聪明钱把币转到自己另一个钱包，也会被当成卖出。
6. **模拟盘按实时价格成交**，比真实成交乐观一些。
